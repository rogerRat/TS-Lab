#### ancUni 与 Traj 的零概率机制

ancUni 的零概率比例高于 RAGE，与两臂使用不同初始 q 或 eta 无关：每任务二者共用 q=16、eta=1 和相同粗锚点集合，粗层目标均为 83,330 个 source 锚点；八任务合计为 666,640 个 source 粗锚点和 8,700 个 reference 粗锚点。差别在细化轮数：`ancUni` 配置为 R=0，只使用粗锚点；`rage` 配置为 R=1，在相同粗层上再做一轮细化。因此这是一组“是否细化”的算法消融，并非总梯度计算量匹配的比较。两臂的粗梯度均从 step-1000 热身梯度缓存复用；RAGE 细化的名义目标为 607,690 个 source 与 8,595 个 reference 梯度，实际新算 591,351 个 source 与 8,595 个 reference 梯度（其余 source 细锚点命中缓存），ancUni 没有细化梯度计算。最终概率描述符包含 RAGE 1,277,117 个 source 锚点位置（其中 1,247,034 个锚点得分为正），ancUni 666,640 个位置（其中 641,903 个得分为正）。RAGE 额外的正锚点邻域扩大了有支持窗口的范围，所以其零概率窗口比例较低。

Traj 的选择单位确实是整条轨迹：先计算 reference/source 轨迹方向的相似度，再将进入全局 top-ρ 配对的 source 轨迹纳入集合；训练时在该集合内均匀抽轨迹，并在抽中的轨迹内均匀抽合法窗口。故选中轨迹中的每个窗口概率都为正，未选轨迹中的窗口概率为零。这里零概率比例按窗口起点计权，不能用未选轨迹条数占比代替：TIME 2 选中 80/96 条轨迹，未选的 16 条只占全池合法窗口的 4.91%；TIME 8 选中 20/96 条，但这些轨迹仅包含 5.31% 的合法窗口，因此零概率窗口为 94.69%。八任务累计选中 406/768 个“任务×轨迹”位置，正概率支持为 9,849,565/21,330,496 个窗口起点（46.18%）。各任务选中轨迹数可由对应的 `outputs/selection/v1-rage-ads/rolling/<task>/Traj/sampling.json` 中 `fragment_ids` 复核，概率支持计数见上述审计 JSONL。

八任务 MASE 算术均值为 fullRand 1.4788、rage 1.4637、ancUni 1.4744、Traj 1.4905。Traj 的最低 MASE 出现在 FEV 9 和 TIME 3，共 2/8 任务；rage 在 4/8 任务最低，ancUni 和 fullRand 各在 1/8 任务最低。因此“精心设计的 ADS 总体不如轨迹级筛选”不符合本批次平均 MASE：rage 比 Traj 低 0.0268（约 1.8%），但 Traj 确实在两个任务胜出。另一个反直觉点是 Traj 的八任务平均 best-reference 对齐最高（0.2148），而其平均 MASE 最差；梯度对齐改善不能直接等同于下游预测误差改善。

可能的解释包括：Traj 的轨迹聚合与轨迹内均匀采样形成了不同的覆盖/正则化效应；ADS 的局部锚点概率会保留 reference 锚点密度的不均匀影响；梯度余弦只近似当前探针目标，未包含有限训练预算下的优化轨迹和任务特有预测损失。这些是待验证假设，不是本批次能识别的因果解释。单 seed、八任务和不同任务窗口数也限制了泛化结论。辅助指标及对齐—效果描述性相关性见 `downstream-metrics.jsonl` 与 `alignment-outcome-correlations.json`。
- 故障与恢复：首轮 12-worker manager 用时 27.7 分钟，28/32 单元完成；TIME08 四臂训练都到 4,000 步，但滚动评估在短于 TimerXL 最小 96 点输入的历史窗口处报错。TimerXL 推理现对不足 96 点的历史以最早观测值左侧 edge padding，保留所有窗口；已有评估目录通过 `--resume` 接续。先单独恢复 fullRand，再由 12-worker runner 并行恢复其余三臂，四个 TIME08 输出均完成。实际计算耗时为首轮 27.7 分钟加恢复约 18 秒，故障诊断间隔不计为计算时间，也不使用 6.4 小时串行累计值代替本批次实际耗时。
