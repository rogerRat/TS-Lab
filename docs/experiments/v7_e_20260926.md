# V7-e exploratory task loop — 2026-09-26

This is a prospective extension, not a rewrite of V7's original seven-task
main matrix or its three later exploratory tasks. V7's ten-task, two-seed,
three-model, 23-arm result snapshot is generated by
`scripts/report_v7_final.py`; it excludes the legacy reference-centroid
`grad-cos` arm. Four Shape arms must each have exactly 60 accepted cells
before V7-e chooses any method. Rank them by the arithmetic mean of
`100*(1-MASE_arm/MASE_rand)` over the same 60 model×task×seed cells.
Freeze the two highest-ranked Shape arm IDs, exact means and selection rule
at `main-v7-20260923/v7_e_20260926/frozen_shape_choice.json`.
No V7-e task exam result may influence this choice.

Each V7-e task has **11** reported arms: the chosen two Shape aggregations,
the matching two Block and two Traj aggregations, LP-Mirror, TSDS, LESS,
rand and untouched orig. The source feasible pool, seed0/1 actual pools,
window protocol, CRB budgets, ranking, model recipes and fixed evaluation
endpoints are inherited from V7: Chronos 3 epochs, TimerXL/TimesFM 4,
all with half-epoch curves. Seed2 is forbidden. Two seeds finish for one task
before the queue enters the next. Gradient assets are prepared first,
then native selections with zero selection BP, native cells, Shape selection
from the *existing* endpoint gradient rows with zero new BP, and Shape cells.
The Shape scorer computes/stores only the two chosen aggregations in this
new namespace. Orig/rand Shape-sidecar cells are verified relabelled copies
of the native task cells, not new training/evaluations.

## Execution and recoverability

Launch `python -m scripts.run_v7_e_queue --parent
/root/autodl-tmp/TS3/outputs/main-v7-20260923 --wait-shape-pid <verified
Shape supervisor PID>` from `/root/TS3` in tmux with `PYTHONPATH=src:.`.
The supervisor waits on a pidfd event, not a polling loop, then verifies all
four Shape arms, freezes the two winners and starts the first candidate.
Runs live under `outputs/main-v7-20260923/extensions/v7-e/<task-id>-20260926`.
Each candidate has its own immutable config at `configs/rags/v7_e_<task-id>.json`
and its own gradient manifest/reference assets/selection/results. Source
gradient payloads and source CRB/TSDS features are field-validated and
hardlinked from V7. No parent cache/result is deleted or rewritten.

The existing event-driven native task runner schedules Chronos on GPU0 and
TimerXL/TimesFM on GPU1, with free training slots allowed to claim other
ready model work. Shape phases run three model workers per selected arm.
The queue audits the 9 native arms and 2 Shape arms for both seeds and all
three models (66 cells/task), selection zero-BP receipts, exact identities and
half-epoch endpoints before writing `v7_e_task_complete.json` and advancing.
Existing completed cells/receipts are reused on restart. A `STOP` file in
`main-v7-20260923/v7_e_20260926/` causes a graceful stop at the next task
boundary; active task cells finish. Resource admission remains fail-closed.
After the pinned list is exhausted, the queue records
`candidate_list_exhausted` and stops instead of repeating tasks; the finite
TIME catalog cannot supply infinitely many genuinely new tasks. Add a new
independently justified candidate batch before then if the user has not
stopped the extension. Kimi supervises GPU utilization, disk, receipts and
failure recovery without deleting caches or restarting a live same-model
worker.

V7-e outcomes must be reported separately from the ten tasks used to select
the method pair. Selection time, physical selection storage, shared gradient
assets, new BP and training/evaluation time stay separate cost columns.
