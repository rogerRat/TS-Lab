# V7 外部数据选择基线预研（2026-09-26）

用户目标：保留一个来自独立工作的横向基线；LTSV 不考虑。现有 V7 `grad-cos` 展示为 `gradcos-legacy`，不能冒充双侧逐窗口余弦；原始身份和结果不变。

## 候选结论

首选做 **TimeLAVA 的有界适配试点**，但不能把它直接写作“原版 TimeLAVA 在 V7 全池运行”。[论文](https://arxiv.org/abs/2606.18729)与[作者代码](https://github.com/lww28/TimeLAVA)均面向时序段估值，利用小波距离与非平衡最优传输，不需要三个学生模型的反向传播。这比另训代理模型更适合作为独立方法学对照。它不是当前 V7 的现成即插即用臂：作者 API 接受各一条连续 `X_eval` / `X_ref` 时序，V7 是多条分离轨迹与上千万合法窗口，必须保留轨迹边界并定义段值到 V7 采样概率的映射。

作者[实现](https://raw.githubusercontent.com/lww28/TimeLAVA/main/src/timelava/core.py)会创建稠密 `n_eval × n_ref` 小波距离矩阵，并返回同尺寸传输矩阵；[求解器](https://raw.githubusercontent.com/lww28/TimeLAVA/main/src/timelava/uot.py)用 float64，对默认 `reg=0.01` 的迭代上界至少 5000 次，每次在完整矩阵上做两轮 log-sum-exp。仅以 136,087 个源代表和 169 个参考代表为**假设性规模**，单矩阵约 184 MB、两矩阵至少 368 MB，迭代最多涉及约 1150 亿对元素/方向；真实原版分段数取决于 `L/S`，不能用 V7 梯度锚点数冒充实测。按 V7 所有窗口直上则显然不经济。作者代码未处理多轨迹身份、概率输出或 V7 训练入口。

可实施的试点应单独命名 `TimeLAVA-V7-adapted`：先固定一个七任务内参考量小的任务（`time_cphl_h` 的 V7 参考梯度 BP 需求为 169，但这**不是** TimeLAVA 参考段数），一个 seed，三模型共用同一原始时间序列特征；按窗口协议区分 CT 与 TimerXL。逐轨迹抽取固定数量、预先声明的非重叠段，使用作者原始小波特征与 UOT 方程打分，再以预先声明的窗口映射扩展到训练池；核对所有合法窗口正支持、无池外窗口、源/参考/test 分离、固定暴露预算及完整选择成本。试点必须报告实际段数、矩阵峰值内存、壁钟与选集字节；若实际扩至七任务两 seed 的 ETA 不可接受，停止，不把试点冒充完整横向结果。段预算和窗口映射是方法适配，不是作者原版结果，正式启动前应冻结在独立协议/配置中。

其他候选：[TimeInf 官方代码](https://github.com/yzhang511/TimeInf)是时序影响函数，但需要指定代理模型和估值目标，适配三种预训练学生的成本/语义高于上述有界试点；[Data-OOB 官方代码](https://github.com/ykwon0407/dataoob)需要 bagging 训练代理模型，不符合快速低成本；[KNN-Shapley 官方代码](https://github.com/AI-secure/KNN-PVLDB)为 kNN 分类估值，要引入人为标签/特征定义，作为预测任务横比的解释力较弱。LTSV 按用户要求排除。

当前只完成方法筛选与容量审计，**尚未生成 TimeLAVA 选择概率、训练或性能结果**。不把独立研究结果混入现有 V7 二十臂身份，也不触碰运行中的 shape 补做。
