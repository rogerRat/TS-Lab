## A. 已确认的实现缺口或边界差异

### A1. 新预算尚未落到正式配置

文档最新决定为覆盖/误差/分裂 4%/2%/2%，总密度8%。远程 `configs/rags/full_pool.yaml:18` 仍为 2%/2%/0.5%；现有开发配置也是旧值。`CRBConfig` 类默认甚至为 1%/0.5%/0.5%，不能把类默认当正式有效配置。正式 worker 读取 `config['crb']`，所以新文档不会自动改变执行。

类型：已明确待实施的新决定，不是已有历史结果计算错误。

### A2. 正式训练入口没有传递已决定的模型专属训练配方

文档远程更新及 `shared_tasks_10.json` 规定三模型不同的 weight decay、betas、调度、最低学习率、micro batch，统一裁剪1、warmup0、调度总长度6 Epoch。`full_pool_worker.py` 调用 `run_arm_training` 只传学习率、Epoch和全局 `train_batch`，没有传这些优化器参数。`train_eval.py:fine_tune` 固定默认 weight_decay=0.01，直接构造 AdamW，未实现该入口的调度、梯度裁剪和 micro batch 累积。

尤其 TimeMoE 需要有效batch64/micro16、betas(0.9,0.95)、WD0.1且bias/norm不衰减；当前生产模板全局train_batch32，训练函数没有上述分组与累积。Chronos应WD0。不能将探测工作区的配方已实现等同于正式 worker 已接通。

类型：正式执行链缺口，影响实际训练协议。

### A3. TimesFM 的2.625 Epoch被正式训练函数拒绝

冻结记录为2.625。`train_eval.py:run_arm_training` 对重采样窗口要求 `source_epochs * 2 % 1 == 0`，仅接受半整数或整数；2.625会直接报错。已从源码AST提取该条件单独执行：1、2通过，2.625触发 `Full-pool observation schedule requires positive half/integer epochs`。没有加载模型或训练。

### A4. 旧 trajectory_level 仍在正式矩阵，新 RAGS-Traj 未接入

实验稿§5.1已将旧独立估值臂撤下，要求复用 RAGS 原始锚点、按重建窗口贡献聚合轨迹。远程 `full_pool.py:ARMS`、生产模板仍含 `trajectory_level`；正式配置校验要求该ARMS列表。`assets/gradient/prepare.py` 对该旧臂调用 `trajectory_positions` 独立提出均匀窗口需求，而不是按RAGS缓存重建质量聚合。检查的正式入口未见新 RAGS-Traj 分支。

类型：文档已明确待实现的消融缺口；旧结果不能改名代替。

### A5. RAGS-Uniform只有底层采点开关，没有完整消融执行与配对验收

`crb.py` 已支持 `error_placement='uniform'`，确实按最长区间追加，覆盖与检测保留。但正式 `ARMS` 中没有该变体，也没有实验稿§4—5要求的“两任务、三种子、实际K逐轨迹配对”编排与产物验收。相同预算上限不能保证相同实际分裂次数，底层开关存在不等于实验已实现。

### A6. 分裂预算按“前若干标记区间”截断，而不是按实际新增梯度循环耗尽

方法稿伪代码是 `while marked非空 且 K_split未用完`。远程 `crb.py` 用 `for interval in flagged[:split_budget]`，flagged已按时间排序；若前面的标记区间相邻锚点间没有内部合法起点，直接丢弃且不增加 `split_used`，但仍占列表截取的名额，后面可切区间不能补位。

例如标记列表前两项依次为不可切、可切，split_budget=1：实现不新增梯度、第二项记为budget ban，尽管实际分裂预算未使用。应决定保留这个队列规则并写清楚，还是修正为按实际新增梯度计预算；本次只列差异。

### A7. 成本记录没有覆盖梯度资产准备的完整耗时

实验稿要求共同梯度缓存首次计算成本与增量成本分列。正式 worker 先执行 `prepare_gradients`，之后才进入 `SelectionMetrics.measure`；因此 selection_seconds不含该准备阶段。RAGS的 `gradient_computations=0`，另在资产JSON和notes记录计算次数，但准备阶段的完整耗时/峰值没有被同一成本接口记录。不能把现有selection_seconds直接报告为冷启动RAGS总选择耗时。

### A8. 汇总产物未完成文档要求的完整统计

实验稿要求种子波动、配对差异、跨任务汇总、平均名次及差异区间。`full_pool_run.py:summarize` 当前生成每任务每臂的种子平均MASE和相对original/random改进，未生成上述完整统计。原始cell仍可用于后处理，属于报告层缺口，不是已保存MASE的错误。

## B. 当前文档的明确残留或内部冲突

### B1. P10规则一致，C3旧数值及跨投影迁移说法不一致

方法稿规定每模型在开发数据全部真实梯度范数上取P10；实验稿§1.3也说旧Small值不自动迁移。远程 `full_pool_calibration.py` 合并开发source/reference真实窗口范数取 `np.percentile(norms,10)`，`epsilon_protocol.py` 核验模型、revision、投影维度/种子、精度、ckpt，设置epsilon_mu=epsilon_g。

但实验稿决策表C3仍标“0.70388913已冻结”，并写“1024维标定值直接用于4096维主配置”。这与当前身份校验和实验稿后面的规则冲突。当前规则是P10标定，并非固定跨模型数值0.70388913，也不是运行时挑最低10%的块。

### B2. “两端不弱”表述比代码条件严格

方法稿§3.3文字写均值弱而“两端不弱”时分裂，容易被理解成两个端点都超过阈值。代码实际是均值弱，且不满足“两端都弱”，也就是至少一个端点不弱；方法稿伪代码else分支与代码一致。文字应写“至少一个端点不弱”。

### B3. 方法稿仍把逐窗口梯度等同于逐窗口串行前后向

方法稿§3写“各窗口前向共享不了”“每个g都得单独一次反向”。远程 CRBEngineMulti、梯度引擎采用批处理或样本维并行，实验稿§1.2已经承认并行。语义上的独立窗口梯度不要求API层一次只处理一个窗口。应以“真实窗口梯度数”核算，不把数学独立性写成串行实现限制。

### B4. 实验稿仍混入旧模型、共享探针和旧优化器配置

尽管顶端最新说明指向三模型独立冻结配方，决策表D5仍标“无调度、无裁剪”；§2正文及主表说明还写Chronos-small、统一Small探针、一次选择三份部署。远程 `full_pool_models.py` 实际加载Chronos Base/TimesFM/TimeMoE各自模型与梯度引擎，4096维投影、种子42、BF16身份分别记录。旧Small共享选择文字必须标旧或清除，不能作为当前方法解释。

`iclr2027/_draft_ch.tex:243` 起仍写全局预算按轨迹分配、优先级 `(b-a)(1+E)`，残差为方向误差与相对幅值误差的最大值；远程CRB使用三阶段密度、区间平方插值风险 `h^5*c^2/120`。主稿后续还写参考块扰动、多版本入选频率、稳定性约束和保守效用，实验部分列大量旧扫描。

## C. 范围/就绪状态的差异，不能直接判为算法错误

1. **十任务与正式六任务尚未接通。** `shared_tasks_10.json`明确只是开发范围/参数决策，非可启动源池协议；生产validate_config仍锁定MAIN_DATASETS六个旧FEV任务。当前文档也要求开发与正式实验分开，因此不能据此擅自认定正式就必须改为十任务；需要先明确十任务是否同时替代正式考纲。可以确认的是，不能说正式入口已使用共享十任务。
2. **当前锚点诊断不是文档三版本消融。** `/root/TS3-probe/.../anchor_budget_linear.py`的条件是(2,0,0)、(2,2,0)均匀/误差、(2,2,2)、(6,0,0)、(15,1,1)，在五条rank0轨迹上计算逐窗余弦均值，没有(4,2,2)，没有RAGS-Traj和最终分布TV。它是另一组诊断，不能当成实验稿§3—5的完成证据。另一个会话可能已有独立授权，本次不判断其授权范围，也不停止它。
3. **P10机制已接入不代表三模型标定资产全部就绪。** 活跃进程仍在重算TimeMoE BF16 P10；远程window_gradient_protocol明确旧FP32不能混用。应以各模型实际epsilon.json身份判断就绪状态，而不是以校验函数存在就宣称全部可运行。
4. **块级权重不等于所有索引都是O(块数)。** RAGS没有逐窗口概率表，但当前ResampledWindows仍保存逐合法起点的window_locations/window_ids/unit_positions，训练曝光计数也按窗口保存。文档允许合法起点索引，故不是数学不一致；若声称整个存储仅O(块数)，则超出现实现。
