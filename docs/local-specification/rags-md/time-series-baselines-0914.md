## 当前决策（覆盖初次调研的推荐顺序）

2026-09-14 用户确认：**TimeLAVA 仅列为备选，不纳入当前主实验。** 它虽使用 Reference，但模型无关的分布匹配估值与当前“面向具体学生的 Reference 引导训练效用估值及外部源池重采样”场景不够贴合。此决定不以计算成本是否可接受为转移；有公开代码或小规模可运行也不构成自动接入理由。现有实验方案不变，后续启用须另行确认。

## 接入前必须厘清的边界

以下仅在将来重新确认采用相应候选时供参考，不是当前接入计划或已决定的算法改造。

1. **TimeLAVA 先算规模再决定接入。** 论文 §4.3 给出成对距离与 UOT 的复杂度；仅一个稠密 float32 成本矩阵就需约 4nm 字节，求解器通常还需其他状态。分批距离计算不自动解决全局 OT 的内存问题。多轨迹不能首尾拼接产生跨轨迹假窗口；片段/点分数怎样映射到本项目 C=512、H=64 的合法训练窗口，需要明确适配。不能暗中改为每条轨迹一个分数。[复杂度与定义](https://arxiv.org/html/2606.18729v2)
2. **不要把 RAGS 的 Ref 份额硬约束强加给 TimeLAVA。** UOT 允许边缘质量松弛是它的方法特征。公平应体现在可用参考数据一致、适配透明，而不是把不同方法都改成 RAGS 的分配公式。它与 TSDS 均含 OT，但当前 TSDS 为轨迹表征和原生轨迹质量；TimeLAVA 则提供局部时序表征和不同的估值依据。
3. **TSRating 不能先承诺开箱前向评分。** 仓库有训练和评分流程，但 README 表明中间数据未上传，本次没有核实可直接下载的预训练评分器。若无可用权重，要计入标注/LLM、元训练和目标域适配；若可复用，也要披露训练数据来源和潜在评测重叠。[仓库说明](https://github.com/clsr1008/TSRating)
4. **TimeInf 明确实现变体。** 原论文既讨论线性 AR 的直接计算，也讨论 CG、Hessian-free 等近似。若使用线性代理，名称和结论都要说明是代理估值；若采用大模型近似，则需单独验证与原定义的关系，不与 LESS 或 RAGS 共享一份梯度后冒称等价。[计算方式](https://arxiv.org/html/2407.15247)
5. **评分器与重采样部署分开命名。** 对原本做硬选择的方法，保留估值核、接入当前全池概率转换时应说明协议适配，不沿用论文 top-K 作为主实验支持集。估值粒度、窗口覆盖、参考侧使用和首次/复用成本都需记录。非梯度分数不能套用“余弦非正置零”规则。
6. **不增加测试信息与训练优惠。** 候选只能访问现行允许的源池、参考及开发范围；不得用最终测试结果训练评分器或搜索混合比例。同一学生保持已冻结的训练超参数与实际抽取量。模型无关产物若身份一致可跨学生复用，但不能只报告摊销成本而隐去首次成本。

结论：TimeLAVA 留作备选，当前不新增基线。后续筛选优先要求贴合 Reference 引导、目标模型训练效用和外部源池重采样；仅有时序估值或 Reference 输入不足以证明场景适配。正式决策见[实验文档](_exp-0907.md)。
